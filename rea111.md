Да. Ниже даю вариант именно для твоей схемы: **один или два прямых адреса PostgreSQL**, приложение на `asyncpg`, Alembic на `psycopg2`, миграции выполняются до запуска приложения.

Сразу поправлю важную вещь из моего прошлого ответа: **`pool_pre_ping` не подтверждает роль мастера**. Роль проверяется драйвером при создании нового соединения через `target_session_attrs=read-write`. При ошибке на старом соединении мы сбрасываем пул, а безопасную операцию повторяем с новой транзакции.

### `config.py` — замени только свойство `postgres_dsn`

Остальные настройки `Settings` оставь как есть. Импорт `quote_plus` после замены не понадобится; добавь `URL`:

```python
from sqlalchemy.engine import URL
```

Внутри `Settings`:

```python
    @property
    def postgres_dsn(self) -> str:
        hosts: list[str] = []

        for raw_host in self.postgres_hosts.split(","):
            address = raw_host.strip()
            if not address:
                raise ValueError("POSTGRES_HOSTS содержит пустой адрес")

            host, separator, port_text = address.rpartition(":")
            if not separator or not host or not port_text.isdigit():
                raise ValueError(
                    "Каждый адрес POSTGRES_HOSTS должен иметь вид host:port"
                )

            port = int(port_text)
            if not 1 <= port <= 65535:
                raise ValueError(
                    f"Недопустимый порт PostgreSQL: {port}"
                )

            hosts.append(f"{host}:{port}")

        if not 1 <= len(hosts) <= 2:
            raise ValueError(
                "POSTGRES_HOSTS должен содержать один или два адреса"
            )

        if len(set(hosts)) != len(hosts):
            raise ValueError(
                "POSTGRES_HOSTS содержит повторяющиеся адреса"
            )

        url = URL.create(
            drivername="postgresql+asyncpg",
            username=self.db_user,
            password=self.db_password,
            database=self.db_name,
            query={
                "host": tuple(hosts),
                "target_session_attrs": "read-write",
            },
        )
        return url.render_as_string(hide_password=False)
```

В `.env` подходят оба варианта:

```env
POSTGRES_HOSTS=pg-1.example.ru:5432
```

```env
POSTGRES_HOSTS=pg-1.example.ru:5432,pg-2.example.ru:5432
```

Для `asyncpg` через SQLAlchemy у каждого хоста должен быть указан порт. [Документация SQLAlchemy](https://docs.sqlalchemy.org/en/20/dialects/postgresql.html#multihost-connections).

### `connection.py` — замени целиком

```python
import json
from collections.abc import AsyncIterator
from contextlib import asynccontextmanager

from sqlalchemy import text
from sqlalchemy.exc import DBAPIError, SQLAlchemyError
from sqlalchemy.ext.asyncio import (
    AsyncEngine,
    AsyncSession,
    async_sessionmaker,
    create_async_engine,
)

from app.config import get_settings
from app.database.models import Base, SCHEMA


settings = get_settings()

engine: AsyncEngine = create_async_engine(
    settings.postgres_dsn,
    pool_pre_ping=True,
    pool_size=settings.postgres_pool_size,
    max_overflow=settings.postgres_max_overflow,
    pool_recycle=settings.postgres_pool_recycle_seconds,
    pool_timeout=10,
    connect_args={
        "timeout": 5,
        "statement_cache_size": 0,
        "prepared_statement_cache_size": 0,
    },
    json_serializer=lambda value: json.dumps(value, ensure_ascii=False),
)

session_factory = async_sessionmaker(
    bind=engine,
    class_=AsyncSession,
    expire_on_commit=False,
)


def get_database_engine() -> AsyncEngine:
    return engine


def is_failover_error(exc: DBAPIError) -> bool:
    if exc.connection_invalidated:
        return True

    original = exc.orig
    sqlstate = (
        getattr(original, "sqlstate", None)
        or getattr(original, "pgcode", None)
    )

    if sqlstate is None:
        driver_error = getattr(original, "__cause__", None)
        sqlstate = (
            getattr(driver_error, "sqlstate", None)
            or getattr(driver_error, "pgcode", None)
        )

    if sqlstate is None:
        return False

    if sqlstate.startswith("08"):
        return True

    return sqlstate in {
        "25006",  # read_only_sql_transaction
        "57P01",  # admin_shutdown
        "57P02",  # crash_shutdown
        "57P03",  # cannot_connect_now
    }


@asynccontextmanager
async def session_scope() -> AsyncIterator[AsyncSession]:
    try:
        async with session_factory() as session:
            async with session.begin():
                yield session
    except DBAPIError as exc:
        if is_failover_error(exc):
            await engine.dispose()
        raise


async def check_database() -> bool:
    try:
        async with engine.connect() as connection:
            await connection.execute(text("SELECT 1"))
    except SQLAlchemyError:
        return False
    return True


async def initialize_database() -> None:
    if not settings.database_auto_create_schema:
        return

    async with engine.begin() as connection:
        await connection.execute(
            text(f'CREATE SCHEMA IF NOT EXISTS "{SCHEMA}"')
        )
        await connection.run_sync(Base.metadata.create_all)
```

Здесь нет ретрая внутри `session_scope()` по принципиальной причине: после ошибки транзакция закончена, а контекстный менеджер не умеет заново исполнить код репозитория. `await engine.dispose()` заставляет следующие подключения использовать новый пул и снова выбрать writable-узел. Если оба хоста недоступны, ошибка дойдёт до воркера; он должен оставить задачу для последующей попытки.

`initialize_database()` оставил для твоей локальной среды. На проме, где до приложения выполняется `alembic upgrade head`, поставь:

```env
DB_AUTO_CREATE_SCHEMA=false
```

### `alembic/env.py` — замени целиком

Этот вариант **синхронный**, как твой текущий Alembic. Асинхронный шаблон Alembic для этой задачи не требуется.

```python
from logging.config import fileConfig

from alembic import context
from sqlalchemy import create_engine, pool
from sqlalchemy.engine import make_url

from app.config import get_settings
from app.database.models import Base, SCHEMA


config = context.config

if config.config_file_name is not None:
    fileConfig(config.config_file_name)

target_metadata = Base.metadata

sync_url = make_url(
    get_settings().postgres_dsn
).set(
    drivername="postgresql+psycopg2"
)


def run_migrations_offline() -> None:
    context.configure(
        url=sync_url.render_as_string(hide_password=False),
        target_metadata=target_metadata,
        include_schemas=True,
        version_table_schema=SCHEMA,
        literal_binds=True,
        dialect_opts={"paramstyle": "named"},
    )

    with context.begin_transaction():
        context.run_migrations()


def run_migrations_online() -> None:
    connectable = create_engine(
        sync_url,
        poolclass=pool.NullPool,
        echo=False,
    )

    try:
        with connectable.begin() as connection:
            connection.exec_driver_sql(
                f'CREATE SCHEMA IF NOT EXISTS "{SCHEMA}"'
            )

            context.configure(
                connection=connection,
                target_metadata=target_metadata,
                include_schemas=True,
                version_table_schema=SCHEMA,
            )

            with context.begin_transaction():
                context.run_migrations()
    finally:
        connectable.dispose()


if context.is_offline_mode():
    run_migrations_offline()
else:
    run_migrations_online()
```

У Alembic будет **тот же список хостов**, та же проверка `read-write`, но драйвер `psycopg2`. Миграция применяется один раз к текущему мастеру. Если первый адрес сейчас реплика, драйвер попробует второй.

### Пример репозитория: безопасный повтор GET

Добавь отдельную небольшую функцию для операций, которые можно повторять. **Не оборачивай автоматически все записи**, поскольку при обрыве на `COMMIT` результат записи может быть неизвестен.

```python
import asyncio
import random
from collections.abc import Awaitable, Callable
from typing import TypeVar

from sqlalchemy.exc import DBAPIError

from app.database.connection import is_failover_error


T = TypeVar("T")


async def retry_read(
    operation: Callable[[], Awaitable[T]],
    attempts: int = 3,
) -> T:
    for attempt in range(attempts):
        try:
            return await operation()
        except DBAPIError as exc:
            if not is_failover_error(exc) or attempt == attempts - 1:
                raise

            delay = 0.5 * (2 ** attempt) + random.uniform(0, 0.2)
            await asyncio.sleep(delay)

    raise RuntimeError("Недостижимое состояние retry_read")
```

Применение к существующему `DialogReportRepository.get()`:

```python
async def get(self, call_id: str) -> DialogReportEntity | None:
    async def read_once() -> DialogReportEntity | None:
        async with session_scope() as session:
            row = await session.get(DialogReport, call_id)
            if row is None:
                return None
            return DialogReportEntity.model_validate(row)

    return await retry_read(read_once)
```

Для записей твои `ON CONFLICT` и уникальный `call_id` уже дают основу для безопасного повтора, но каждую такую операцию надо рассматривать целиком: например, сохранение входного диалога **вместе с созданием задачи** в одной транзакции. Пока общий `retry_read` к записям не применяй. При ошибке воркер повторит задачу своим штатным механизмом.

### `main.py` — две точечные правки

Полный корпоративный `main.py` я не вижу, поэтому не стану выдумывать его инфраструктурные блоки. Замени именно эти части:

1. Удали `global_failover_handler`, который ищет слова в `str(exc)` и вызывает `failover_engine()`. Также убери импорт `failover_engine`. HTTP-обработчик не поймает ошибки воркера и не повторит упавшую транзакцию.
2. В `finally` жизненного цикла оставь закрытие пула **последним**:

```python
scheduler.shutdown()
await worker.stop()

worker_task.cancel()
await asyncio.gather(worker_task, return_exceptions=True)

# Закрытие внешних анализаторов и GigaChat provider — как у тебя сейчас.

await get_database_engine().dispose()
```

Периодический пинг раз в час не добавляй. `pool_pre_ping=True` проверяет выдаваемое соединение, а `pool_recycle` ограничивает его возраст. При обнаруженном переключении пул сбрасывается и новое соединение выбирает доступный для записи хост. Успешность во время самого переключения зависит от длительности переключения и повторов задач; обещать отсутствие любой единичной ошибки в этот момент было бы неправильно.
